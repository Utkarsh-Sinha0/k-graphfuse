# Sinha GraphFuse: public industry reference comparison

Saved before receiving any performance result from this new run. The numerical core and previous benchmark archive remain unchanged.

The workload is the published Graphalytics `datagen-7_5-fb` PageRank reference: 633,432 vertices, 34,185,747 file edges, undirected unweighted traversal, uniform initialization, damping 0.85 and exactly ten updates. The official downloaded per-vertex reference is the acceptance authority. Its source file and archive hashes are recorded. This is a standard dataset and reference task, not an officially audited or accepted Graph Data Council submission. [Official dataset and reference collection](https://ldbcouncil.org/benchmarks/graphalytics/datasets/).

Comparators executed on the same Kaggle machine are Sinha's existing GPU engine, actual NVIDIA `pylibcugraph 26.10.0`, and the unmodified released ArcadeDB `26.10.1` embedded PageRank implementation. Sinha returns original probability scores in the timed call. The cuGraph call returns native probabilities: there is no timed conversion into Sinha's symmetric coordinate system. Output identifiers and probability values are checked against the same official reference, with a maximum per-vertex relative error of 1e-4. Every rejected configuration remains visible.

Sinha evaluates the exact finite polynomial equivalent to ten PageRank updates after a similarity transformation. With beta=0.85, coefficients are `(1-beta)*beta^k` for k=0,...,9 and `beta^10` for k=10. The input is uniform probability divided by square-root degree; the output is multiplied back by square-root degree inside timing. The compiler receives zero truncation budget. This workload does not demonstrate a novel theorem-driven degree reduction. A direct independent SciPy power iteration checks the polynomial against the official reference before timing.

The source graph must have no dangling vertices for this polynomial representation; the run asserts this rather than quietly changing the graph. Sparse duplicate edges preserve multiplicity. Original file weights are retained for ArcadeDB loading but ignored by this PageRank reference. No graph simplification or top-k-only substitution is permitted.

Each GPU configuration has 31 synchronized wall-time samples, 11 host-output samples, and separately reported preparation and first-call time. Configurations cover FP32/FP64, packing and capture. Actual cuGraph tests both precisions, cached transposed graph and outgoing-weight sums, epsilon=1e-30, cap=10 and nonconvergence reporting enabled. Epsilon zero is avoided because NVIDIA documents that it selects a default tolerance. Early convergence cannot qualify unless the resulting vector still passes the ten-step reference check.

ArcadeDB is downloaded from its official release and checked against its published SHA-256. A small compiled Java wrapper loads the official graph, creates the normal Graph Analytical View and invokes the released `GraphAlgorithms.pageRank` with 0.85/10/BOTH. The implementation is not edited. Preparation is separate, with one warm-up and 31 timed calls. The fresh database is confined to the disposable Kaggle workspace; it never touches existing user databases. The wrapper was compiled against the official released Maven engine jar.

An adoption comparison reports both strongest accepted tested GPU performance and the CPU product result. A scoped GPU improvement still requires at least 10% lower median, a descriptive bootstrap interval above one and no p95 regression. A CPU-to-GPU gain cannot establish global SOTA or a cloud-bill saving. Public Apple M5 timings are shown separately with their hardware and release/snapshot status; they are never used as same-machine speedup denominators.

Full graph projection/import, preparation, cold first call and host-output cost remain distinct from warm compute. This benchmark does not replace the complete graph database service, property queries, transactions, writeback or customer application. Performance and accuracy conclusions wait for downloaded evidence and source-hash verification.
